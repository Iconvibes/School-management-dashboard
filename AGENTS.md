## Environment & Seeding

- **`SEED_DEMO_SCHOOL=1` must be in `.env.local`** for the demo school to exist. The README claims it's on by default in dev, but the code (`demoSeedEnabled()` in `demo-store.js`) requires the env var to be explicitly `"1"`, `"true"`, or `"yes"`. Without it, login shows "No school found" and no accounts are seeded.

## Build & Test

- **`fake-indexeddb` needed for `offline-db.js` tests** — The test file (`tests/offline-db.test.js`) imports `fake-indexeddb/auto` to polyfill IndexedDB in Node.js. Install with `npm install --save-dev fake-indexeddb`. The module caches its DB connection in a private `_db` variable; use the exported `__resetForTesting()` to close the connection and delete the database between tests.
- **`node --test` can't resolve `@/lib/*`** — the `@/` path alias is a Next.js bundler feature. Tests that import from `@/lib/` fail with `ERR_MODULE_NOT_FOUND` unless run with `--import ./tests/register-aliases.js` (which only `tests/register-aliases.js` sets up). Only tests importing via relative paths (e.g. `../src/lib/permissions.js`) work with plain `node --test`.
- **`register-aliases.js` hook quirk: CJS vs ESM** — When the hook intercepts an extensionless relative import (e.g. `./grading`) and returns a `file://` URL, the CJS loader (invoked for files where Node doesn't detect ESM) crashes with `ERR_INVALID_ARG_TYPE`. Fix: only intercept when a `.ts`/`.tsx` file exists; otherwise fall through to `nextResolve` so the CJS loader handles `.js` natively. This was hit when `ranking.js` (CJS context) imported `./grading` (now `.ts`).
- **Next.js auto-assigns a port when 3000 is occupied** — `next dev` picks a random high port (e.g. 57921, 59093). The actual URL is printed in the console output; don't assume port 3000.
- **`npm run lint` is slow (60s+)** — use `npx eslint <specific files>` to lint individual files quickly.

## Architecture & Gotchas

- **IndexedDB keys must not be booleans** — `src/lib/offline-db.js` used `synced: false`/`true` for the IndexedDB `synced` index, but booleans are not valid IndexedDB keys per the spec. `fake-indexeddb` throws `DataError: Data provided to an operation does not meet requirements` at `IDBKeyRange.only(false)`. Some browser implementations are lenient, but the spec only allows strings, numbers, dates, arrays, and binary data. Use `0`/`1` instead.
- **`web-push` must be explicitly installed** — `src/lib/transports/push.js` dynamically imports `web-push` (`await import("web-push")`) but it wasn't in `package.json`. Push notifications fail silently with `"web-push not installed"` reason. Run `npm install web-push` to enable server-side push delivery.
- **VAPID keys required in `.env.local` for push** — `GET /api/push/vapid-key` returns `{ publicKey: null, configured: false }` if `VAPID_PUBLIC_KEY` is missing. The `PushNotificationManager` component silently fails to subscribe. Generate keys with `npx web-push generate-vapid-keys` and add `VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY`, and `VAPID_SUBJECT` to `.env.local`.
- **`useOfflineSync` stale closure on `syncPending`** — The `handleOnline` callback in `useOfflineSync` captures the initial `syncPending` reference before it's declared with `useCallback`. ESLint flags: "Cannot access variable before it is declared." The auto-sync-on-reconnect may use a stale version. Fix: move `syncPending` declaration above the `useEffect`, or use a ref. **Fixed August 2026** — `syncPending` now declared before the `useEffect`.
- **`offlineFetch` catches network errors** — When `navigator.onLine` is true but the network is unreachable (DNS failure, captive portal), `fetch()` throws a `TypeError`. `offlineFetch` now catches `TypeError` specifically and queues the change offline, returning a mock `{ ok: true, offline: true }` response. HTTP errors (4xx/5xx) are NOT caught since the server was reachable. This prevents silent failures on flaky networks.
- **Parent dashboard is intentionally read-only for offline sync** — Parents don't queue writes (no attendance, grades, or fee actions), so `useOfflineSync` is not imported there. The global `OfflineSyncProvider` in `src/app/layout.js` provides offline awareness (banner + pending count) for all pages.
- **Admin dashboard has two undeclared `useState` variables**: `roleConfirm` and `printSheet` are used in JSX (`page.js` ~line 3330 and ~line 3753) but were never declared with `useState`. These cause runtime `ReferenceError` when the dashboard renders. Both must be declared in the state block near the other `useState` calls.
- **`src/lib/log.js` — `isDev` must be a function, not a const** — `const isDev = process.env.NODE_ENV !== "production"` evaluates once at module load. In test environments or when NODE_ENV changes between imports, this gives stale results. Use `const isDev = () => process.env.NODE_ENV !== "production"` so it reads at call time.
- **Windows: `taskkill /PID` breaks in Git Bash** — Git Bash translates `/PID` to a Windows path. Use `powershell -NoProfile -Command "Stop-Process -Id <pid> -Force"` instead.
- **Admin dashboard `page.js` was ~3770 lines, now ~998 lines (74% reduction)** — 19 tab components, 12 modals, tab config, ScheduleHealthCard, and all 30+ action functions were extracted. Actions live in `useAdminActions.js` (1,302 lines), modals in `src/components/admin/modals/`, tabs in `src/components/admin/`. The page is now a thin layout shell: state declarations → data-fetch effects → `useAdminActions()` call → role gates → JSX. All modals use `useAdminShell()` context. The `AdminProvider` value must list every key a tab or modal destructures.
- **Multi-teacher-per-subject is real** — schools have more than one Maths teacher, more than one English teacher, etc. Basic schools can have multiple teachers assigned to the same subject. Any logic that assumes a unique teacher per subject (scope editor, timetable, report cards, attendance) must handle duplicates.
- **Dashboard layout nesting trap (`<main className="flex">`)** — Every dashboard (admin, teacher, student, parent) uses `<main className="flex">` with `<Sidebar>` (fixed-position) + a content `<div className="min-w-0 flex-1 lg:pl-64">`. All page content (inline sections, not portaled modals) MUST be inside that content `<div>`. Placing components outside it (after its closing `</div>`) makes them flex siblings of the content wrapper, causing duplicated columns, broken layouts, and the sidebar appearing on both sides. The parent dashboard had MessagingPanel, GDPR buttons, AttendanceCalendar, GradeTrends, and PaymentHistory outside the wrapper — fixed August 2026.
- **ErrorBoundary pattern** — `src/components/ErrorBoundary.js` is a React class component with `getDerivedStateFromError` + `componentDidCatch`. Every admin tab, modal, and each dashboard view section should be wrapped: `<ErrorBoundary label="Tab Name"><TabContent /></ErrorBoundary>`. The label appears in the fallback UI so users know which section crashed.
- **`useTabFetch` data starts as `null`, not `undefined`** — Destructuring `{ data: foo = [] }` only provides the default for `undefined`. If the API hasn't responded yet or fails, `data` is `null` and `foo.map()` crashes. Use `(foo || [])` for null-safe iteration. This crashed `RolesTab.js` and is a risk in any component using `useTabFetch`.
- **TypeScript proof of concept** — `grading.ts` and `ranking.ts` are the first two TypeScript files. The `register-aliases.js` test hook handles `.js` → `.ts` remapping for both `@/` aliases and relative imports. CJS files (like `ranking.js` before conversion) that import extensionless relative paths need special handling in the hook to avoid `ERR_INVALID_ARG_TYPE`. Turbopack resolves `.ts` imports fine, but explicit `.js` imports of renamed files break — use extensionless imports.
- **Admin standalone pages need shared sidebar** — `Bulk Import`, `Quick Add`, and `From Class Sizes` were standalone pages without the admin sidebar. `AdminLayout.js` wraps them to provide persistent sidebar + topbar. Always use `AdminLayout` for new admin sub-pages.
- **Admin dashboard has dead `timeAgo` function shadowed by import** — A local `timeAgo(iso)` (compact format "2m ago") exists at `page.js:161` for the health card, but the new `import { timeAgo } from "@/lib/relative-time"` (verbose format "2 minutes ago") shadows it. The local function is never called anywhere — it's dead code that should be removed to avoid confusion.
- **`PRE_CACHE_URLS` SW message handler is restricted** — `public/sw-enhanced.js` listens for `{ type: "PRE_CACHE_URLS", urls }` messages to pre-cache routes, but no client code currently sends this message. The handler is now restricted to an allowlist of dashboard routes only (`PRE_CACHE_ALLOWLIST`) to prevent caching arbitrary URLs. **Fixed August 2026** — restricted to safe allowlist.


- **Platform admin portal is completely separate from school portals** — The platform admin login at `/platform/login` uses `PLATFORM_ADMIN` role, has its own layout (`src/app/platform/layout.js`), and shares zero UI with school admin/teacher/student/parent dashboards. Schools must NEVER see platform admin links, login options, or dashboard content. The platform admin sidebar has a unique dark theme with icon-only nav that expands on hover (desktop) or via hamburger (mobile).
- **Platform admin login must not appear on school login page** — The school login page (`src/app/login/page.js`) lists schools from `/api/schools`. The internal "EduTrack Platform" school is filtered out by `searchSchools()` in `src/modules/school/store.js` via `.filter((s) => !s.isPlatformSchool)`. If you add new platform schools, make sure they have `isPlatformSchool: true`.
- **Platform store stubs in mongo-store.js** — The webhook, alert, audit, impersonation, and digest functions are stubs in `mongo-store.js` (return empty arrays / null). They need real Mongoose implementations before deploying with MongoDB. The contract test ensures signatures match.
- **Impersonation cookie propagation** — The impersonate API sets a new auth cookie and returns the impersonated user, but the admin dashboard client-side me-gate may redirect to login during the transition. The API-level impersonation works correctly (verified via /api/auth/me); the timing issue is in the browser redirect flow.
- **Billing enforcement in policy.js** — The `requireAuth` function checks subscription status for non-admin logins. Expired schools block teachers/students/parents. This check only runs in Mongo mode (demo store has no real subscription data).

## Files That Change Together

- **PWA stack must be kept in sync** — `src/components/PwaRegister.js` registers the SW, `public/sw-enhanced.js` is the active service worker, `src/lib/offline-db.js` provides IndexedDB storage, `src/hooks/useOfflineSync.js` provides the React hook + `OfflineSyncProvider`, and `src/components/PushNotificationManager.js` handles client-side push subscription. Changing one often requires updating the others (e.g. new cache strategy in SW → verify `offline-db.js` cache keys match).
- `src/lib/demo-store.js` ↔ `src/lib/mongo-store.js` — any store function signature change must be mirrored in both, or "works in demo but not Mongo" bugs result. The `dual-store-contract.test.js` (214 lines) catches signature drift.
- `src/app/admin/dashboard/page.js` ↔ `src/components/admin/context/AdminContext.js` — the AdminProvider `value` prop must list every key a tab component destructures via `useAdminShell()`. Adding a new tab with new context keys requires updating both files.
- `src/lib/permissions.js` ↔ `src/lib/portal-guard.js` ↔ `src/lib/roles.js` — adding a role requires updating all three plus `src/models/User.js` enum, `src/lib/demo-store.js` seed, `src/app/login/page.js` ROLES list, and `src/components/Sidebar.js`. The full checklist is in README.md ("Adding a new role").
- **Platform module stack** — `src/modules/platform/` (store functions) ↔ `src/lib/demo-store.js` (re-exports + snapshot) ↔ `src/lib/mongo-store.js` (stubs). New platform features need all three updated. The `dual-store-contract.test.js` catches signature drift.
- **Platform admin sidebar** — `src/app/platform/layout.js` manages the sidebar nav. New platform pages need a nav entry added here. The sidebar uses a unique dark theme and icon-only design.
- **Webhook auto-dispatch** — `src/modules/platform/webhooks.js` `dispatchWebhook()` is called by `createPlatformAlert()` in `src/modules/platform/store.js`. New alert types automatically fire webhooks. Webhook format (Slack/Discord/generic) is handled by `formatPayload()` in the webhooks module.
